# WorkOrder on iOS and Android

The mobile apps are the same code as the web console. There is no second
frontend: `web/public` is assembled into a static bundle and shipped inside the
native binary, so the app opens on a jobsite with no signal.

This document is the handoff. Everything up to `npx cap add` has been done and
is in the repository; the native projects and the store builds have to be made
on a Mac, which is the part that could not be done here.

## What is already in the repository

| Piece                | Where                                                               |
| -------------------- | ------------------------------------------------------------------- |
| Bundle assembly      | `scripts/build-mobile.mjs` → `dist-mobile/`                         |
| Capacitor config     | `capacitor.config.json`                                             |
| Native bridge        | `web/public/native.js`                                              |
| Bearer auth (native) | `backend/auth-tokens.cjs`, `backend/migrations/014-auth-tokens.sql` |
| Secure token storage | `web/public/secure-store.js`                                        |
| Camera capture       | `web/public/native-camera.js`                                       |
| Offline console      | `web/public/sw.js`, `web/public/console-store.js`                   |
| Offline field work   | `web/public/field-sw.js`, `web/public/field-store.js`               |
| Icons + manifest     | `scripts/generate-icons.mjs`, `web/public/manifest.webmanifest`     |

`ios/` and `android/` are generated and git-ignored. Re-running `npx cap add`
recreates them, which means anything hand-edited inside them must be recorded
here — see [Native permissions](#native-permissions).

## Prerequisites

- Node 22.12 or newer (`package.json` sets `engines`)
- **iOS**: macOS, Xcode with Command Line Tools, CocoaPods, an Apple Developer
  account
- **Android**: Android Studio with the SDK and platform tools, a JDK

## Build

```sh
npm install                 # not npm ci — see "Known rough edges"
npm run mobile:build        # assembles dist-mobile/
npx cap add ios             # once
npx cap add android         # once
npm run mobile:sync         # rebuild the bundle and copy it into both projects
npx cap open ios            # or: npm run mobile:ios
npx cap open android        # or: npm run mobile:android
```

`mobile:build` points the app at `https://work-order-eta.vercel.app` by
default. Override it per build:

```sh
WORKORDER_API_BASE=https://staging.example.com npm run mobile:build
```

### Why the bundle is assembled rather than copied

`web/public/*.js` are raw ES modules — there is no bundler in this project —
and they are served at `/assets` by Express with the console shell rendered from
an EJS template. A Capacitor bundle has neither a server nor EJS. The script
therefore:

1. copies `web/public/**` to the bundle **root**, not an `assets/` subfolder, so
   every relative `./ui.js` import keeps resolving untouched;
2. renders `index.html` from `web/views/index.ejs` and rewrites `/assets/x` to
   `./x`, keeping `field.html` as a second entry point;
3. stamps in the API base and client version as `workorder-config.js`;
4. **refuses to emit a bundle containing an absolute path**, because such a path
   resolves against the app bundle instead of the API and fails silently at
   runtime.

That last check is load-bearing. If it trips, the fix is almost always to ask
`native.js` for `assetUrl()` / `homeHref()` rather than hard-coding a path.

## Native permissions

`ios/` and `android/` are regenerated by `cap add`, so these have to be
re-applied after a fresh generate. A missing usage string **crashes the app on
first use** rather than failing review.

### iOS — `ios/App/App/Info.plist`

| Key                                   | Suggested string                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------------------- |
| `NSCameraUsageDescription`            | WorkOrder uses the camera so you can photograph site progress for a daily report.  |
| `NSPhotoLibraryUsageDescription`      | WorkOrder opens your photo library so you can attach site photos you already took. |
| `NSLocationWhenInUseUsageDescription` | WorkOrder records where you clocked in so your hours carry a jobsite location.     |
| `NSFaceIDUsageDescription`            | WorkOrder uses Face ID to unlock your account on this device.                      |

Push also needs the Push Notifications capability and a Background Modes →
Remote notifications entry, added in Xcode's Signing & Capabilities tab.

### Android — `android/app/src/main/AndroidManifest.xml`

`android.permission.CAMERA`, `ACCESS_FINE_LOCATION`, `ACCESS_COARSE_LOCATION`,
`INTERNET`, and on API 33+ `POST_NOTIFICATIONS` — which must also be requested
at runtime, not just declared.

## Signing and release

**iOS.** Set the bundle identifier to `app.workorder.mobile` (or change
`appId` in `capacitor.config.json` and re-run `cap sync`). Select your team
under Signing & Capabilities, bump `CFBundleShortVersionString` and
`CFBundleVersion`, then Product → Archive → Distribute App → TestFlight.

**Android.** Generate an upload keystore once:

```sh
keytool -genkey -v -keystore workorder-upload.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Keep it out of the repository. Reference it from
`android/keystore.properties`, bump `versionCode` and `versionName` in
`android/app/build.gradle`, then Build → Generate Signed Bundle (AAB) and
upload to the Play Console's internal testing track.

## Store review

Two guidelines this app specifically has to clear:

- **4.2 Minimum Functionality.** A wrapper around a website gets rejected. The
  camera, geolocation, push, biometric unlock and genuine offline operation are
  what answer this — lead with them in the review notes.
- **5.1.1(v) Account deletion.** Required because the app offers account
  creation. Implemented at `DELETE /api/me`, reachable from My profile →
  Delete account. Point the reviewer at it; it is easy for them to miss.

Also prepare: privacy policy URL, data-collection disclosures (account data,
photos, precise location, device identifiers for push), and a demo account with
an awarded scope so a reviewer can actually reach the field screens.

## The acceptance test that matters

Everything else is detail next to this one, because it is the reason the app
exists:

1. Sign in on a real device, open a project with an awarded scope.
2. Put the device in airplane mode.
3. Open the app cold. The shell must render, with the banner saying it is
   showing the last synced data.
4. Clock in against the scope, then clock out. Add a daily report with a photo.
5. Restore the network and reopen the app.
6. The queued time syncs **exactly once**.

Step 6 is not luck. Each queued batch carries a `request_key`
(`web/public/field-store.js`) and the server deduplicates on
`(user_id, request_key)` in `backend/field.cjs`, so a repeated sync is a no-op
rather than double-billed hours.

## Testing

```sh
npm test                    # unit + integration, on embedded Postgres
npm run test:console        # browser suite on a throwaway database (port 3210)
```

Two environment traps worth knowing:

- `embedded-postgres` **refuses to run as root.** Both suites need a non-root
  user; in a container that means creating one and `chown`-ing the checkout.
- Playwright writes `test-results/` into the checkout, so a read-only or
  root-owned tree needs `--output=<writable dir>`.

## Known rough edges

- **`npm ci` fails.** `package-lock.json` and `package.json` disagreed about
  `stripe`; the dependency is now declared, but regenerate the lockfile
  (`npm install`) before relying on `npm ci` in CI.
- **The console browser suite is substantially red on `main`, and was before
  this work.** Most of `tests/console/console.spec.cjs` looks for a navigation
  landmark named "Main navigation" that the sidebar stopped rendering when it
  was reorganised into Work / People / Account groups. The specs need updating
  to the current structure; until then the suite cannot tell you much.
- **`tests/ui/` and `playwright.config.cjs`** test the retired Electron
  localStorage prototype and start a `server.cjs` that no longer exists. They
  want deleting or rewriting.
- **Safe-area CSS is unverified on hardware.** `env(safe-area-inset-*)` resolves
  to 0 in a headless browser, so the notch and home-indicator padding needs a
  look on a real device.
- **Push has no provider wired.** The client and server plumbing are not built
  yet; see the repository issues before promising it in a release.
