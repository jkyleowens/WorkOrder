Offline field time: sync sequence

How a crew's hours travel from a phone with no signal to a timesheet row, as implemented in field.js, field-store.js and FieldService.syncTime. Retries are safe because the server remembers every request key.

Guarantees today

  • Retries never duplicate hoursUNIQUE (user_id, request_key) on field_time_batches plus a payload hash check
  • Two tabs cannot clobber a queueone localStorage key per item and a Web Lock around each sync run
  • Private data stays out of cachesthe service worker caches the static shell; sessions, records and photos are never cached

Changes in this plan

  • Sync on reconnect R5listen for the online event so crews don't have to reopen the page
  • Conflict review screen R5show the server's overlapping entries beside the queued item, with fix or discard
  • IndexedDB for photos and documents R6localStorage stays for time; binary payloads move to IndexedDB (decision D5)
